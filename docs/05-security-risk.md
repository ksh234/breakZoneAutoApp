## 1. 시크릿 관리

| 시크릿 | 위치 | 규칙 |
|---|---|---|
| 키움 App Key/Secret (demo/real) | 개발: engine `.env` / 실전: **OS 키체인**(Windows 자격증명 관리자) 또는 클라우드 시크릿매니저 | 깃 커밋 금지, 로그 출력 금지 |
| Supabase `service_role` | engine `.env`(서버 전용) | **앱에 절대 미포함** |
| Supabase `anon` | 앱 | 공개 가능(RLS로 보호) |
| Firebase 서비스계정 (선택 · Phase 5-B 푸시 채택 시) | Edge Function secret | 깃 금지 |

- `.gitignore`: `.env`, `.env.*`, `*.local`, `google-services*.json`, `*serviceAccount*.json`, 키체인 export 등.
- 토큰/키를 콘솔·이벤트·DB에 **평문 기록 금지**. 마스킹 유틸 사용.
- 실전 키는 개발 PC와 분리(가능하면 실전은 클라우드 시크릿매니저에서만).

## 2. 리스크 가드 (봇 강제 — docs/03 §3 재확인)

- 종목당 한도 / 보유수 상한 / 현금 검증 / 평가손실 한도 / 가격 sanity / 중복주문 가드 / 수량 검증. (구현: `strategy/risk.py::ok_buy·ok_sell`)
- **mode='real' 강제 한도:** 실전에서는 코드가 아래를 **하드 상한**으로 강제(설정이 더 커도 클램프). 현재 `risk.clamp_real_mode` 는 골격만 — Phase 7에서 값 확정:
  - 초기 `per_stock_krw` 소액(예: 카나리 100,000~300,000).
  - `max_positions` 축소.
  - `max_unrealized_loss_krw` 보수적.
  - 규칙 위반 시도 시 주문 차단 + `critical` 이벤트.

## 3. Kill-switch (다층)

1. **앱 버튼**(2단계 확인) → `kill` 명령.
2. **서버 자동:** 치명 오류/일손실 초과/브로커 반복거부 → 자동 kill.
3. **동작:** 신규진입 즉시 중단 → 보유 **전량 시장가 청산** 시도 → `stopped` → `critical` 이벤트(인앱 알림, 채택 시 푸시).
4. 청산 실패분은 재시도 + 앱에 명확히 노출(수동 개입 유도).

## 4. 이중 실행 방지 (집 PC ↔ 클라우드)

같은 키움 계좌에 봇이 둘이면 **이중 주문** 위험. 방지:
- **분산 락:** Supabase에 `bot_lock`(owner, holder_id, heartbeat_at). 봇은 시작 시 락 획득(최근 heartbeat 없을 때만) → 주기 갱신. 락 미보유 봇은 매매 금지(관찰 모드).
- 또는 운영 규칙으로 "동시에 하나만 실행"을 물리적으로 보장(이관 시 구 봇 종료 확인).

## 5. 장애 시나리오 → 대응 (모두 `events` 인앱 알림, 푸시 채택 시 푸시도)

| 시나리오 | 감지 | 대응 |
|---|---|---|
| 봇 다운/크래시 | 하트비트 정지 | 앱 "연결 끊김" + (클라우드)자동 재시작. 미체결 주문 상태 점검 |
| 네트워크 단절 | 요청 실패/재연결 | 오프라인 버퍼링 후 flush, 지속 시 신규진입 보류 |
| 토큰 만료/인증 실패 | 401 | 재발급 재시도, 실패 지속 시 정지+알림 |
| 주문 거부(reject) | 응답코드 | 사유 로깅+이벤트, 반복 시 해당 종목 차단 |
| 부분체결 | 체결조회 | 잔량 추적, 포지션/주문 상태 정합 유지 |
| Rate limit(429) | 응답 | 백오프+큐, 임계 초과 시 주기 완화 |
| 시세 이상치 | sanity | 해당 틱 무시, 주문 sanity가 2차 방어 |
| 이중 실행 | 락 상실 | 매매 중단, 알림 |

## 6. 데이터 정합성

- 주문 상태기계는 봇이 소유. Supabase는 미러. 재시작 시 브로커 잔고/미체결을 **재동기화**(source of truth = 브로커).
- 봇 재시작 시 브로커에서 positions/미체결을 다시 읽어 Supabase를 재구성(로컬 상태 맹신 금지).
